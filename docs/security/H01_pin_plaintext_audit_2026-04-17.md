## 이번 세션 범위
- 수행: 평문 저장/비교 여부 점검 및 위험도 기록
- 미수행: 해시 전환, 백필, PIN 자리수 변경

## 증거 기반 점검 결과

### 1) DB 스키마
- `supabase/migrations/20260322000000_add_pin_code_to_employees.sql`
  - `pin_code VARCHAR(4)` 컬럼 추가
  - 평문/해시 여부를 강제하는 제약은 없음

### 2) 저장 경로(직원 등록/수정)
- `src/routes/employees/+page.svelte`
  - 등록 시 `pin_code: newPin`으로 저장
  - 수정 시 `pin_code: pin`으로 저장
- 결론: PIN이 서버/DB에 평문 형태로 전달 및 저장됨

### 3) 검증 경로(QR 출퇴근)
- `src/routes/q/[store_id]/+page.server.ts`
  - `employees`에서 `pin_code` 조회 후
  - `if (pin !== employee.pin_code)`로 직접 비교
- 결론: 평문 비교 로직 사용 중

## 위험도 판단
- PIN 4자리(10,000 경우의 수) 특성상, 평문 저장은 유출 시 즉시 악용 가능성이 큼
- 해시 전환을 하더라도 4자리 체계에서는 탐색 공간이 작아 보안 실효성이 제한적
