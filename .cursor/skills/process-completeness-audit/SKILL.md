# Process Completeness Audit

## 목적
문서/로그/체크리스트/운영 루틴의 완성도를 수동으로 점검한다.

## 사용 시점
- 사용자가 `상태점검`, `완성도`, `기록/분석/점검`, `프로세스 품질`, `운영 갭`을 요청할 때
- 특정 파일(예: `참고 파일/상태점검`)의 근거를 기준으로 현재 수준을 짧게 정리할 때

## 입력 수집
1. 점검 대상 파일/구간을 확인한다.
2. 항목별 근거(파일, 스크립트, 워크플로, 기록 여부)를 추출한다.
3. 실행 증적(로그/산출물/템플릿 강제 여부)이 있는지 확인한다.

## 갭 등급 프레임 (A/B/C)
- A `관리 가능(기록)`:
  - 현재 운영 리스크가 낮고, 개선은 후순위 가능
  - 예: 표현 통일, 보조 문서 미정리
- B `개선 필요(스프린트 내)`:
  - 당장 장애는 아니지만 누적 시 품질 저하 가능
  - 예: 근거는 있으나 운영 증적이 누락된 상태
- C `즉시 보완(우선 처리)`:
  - 운영/배포/데이터 정확도에 직접 리스크
  - 예: 핵심 점검 루틴 부재, 필수 검증 누락

## 판정 규칙
1. 근거 파일/설정이 확인되면 `현재 상태`로 인정한다.
2. 근거는 있지만 실행 증적이 없으면 기본 B로 판정한다.
3. 장애/배포 실패/데이터 오류 가능성이 크면 C로 상향한다.
4. 리스크가 낮고 운영 영향이 미미하면 A로 하향 가능하다.

## 출력 템플릿 (고정)
아래 한 줄 형식을 항목별로 반복한다.

`- [항목명]: 현재 상태=... / 갭 등급=A|B|C / 다음 액션 1줄=...`

## 출력 규칙
- 반드시 한국어로 작성한다.
- 항목당 1줄을 유지한다.
- `다음 액션 1줄`은 실행 가능한 명령형 문장으로 쓴다.
- 모호한 표현(예: "검토 필요") 대신 완료 기준이 보이는 문장으로 쓴다.

## 빠른 체크리스트
- [ ] 점검 대상 파일/구간이 명확한가
- [ ] 항목마다 근거가 있는가
- [ ] A/B/C 판정 이유가 리스크 기반인가
- [ ] 출력이 `현재 상태 / 갭 등급 / 다음 액션 1줄` 형식을 지켰는가

## 예시 출력
- P0-3 헬스 스택: 현재 상태=CI 파이프라인이 PR/푸시마다 자동 실행됨 / 갭 등급=B / 다음 액션 1줄=작업 시작·종료 시 로컬 실행 로그를 공용 폴더에 저장한다.
- P1-5 Knip: 현재 상태=CI 엄격 검증과 로컬 완화 검증을 병행함 / 갭 등급=B / 다음 액션 1줄=상위 30개 이슈를 즉시삭제·보류·의도로 분류한 문서를 커밋한다.
- P1-6 테스트 확대: 현재 상태=핵심 도메인 테스트 파일이 존재함 / 갭 등급=B / 다음 액션 1줄=회귀 시나리오 2개를 추가하고 목표 범위를 문서에 고정한다.
